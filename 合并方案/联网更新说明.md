# 联网更新接入说明（GitHub Releases）

## 现状

更新检测已实现（v129）。后端通过 `ureq`（schannel）拉取 `latest.json`，用 git 提交序号作版本号比较。

## 需要你做的三件事

### 1. 填真实仓库地址

编辑 `app/src-tauri/src/update.rs`，把占位的 `UPDATE_MANIFEST_URL` 改成你的仓库：

```rust
const UPDATE_MANIFEST_URL: &str =
    "https://raw.githubusercontent.com/你的用户名/你的仓库/main/latest.json";
```

（或用 releases 直链：`https://github.com/你的用户名/你的仓库/releases/latest/download/latest.json`，此时 latest.json 需作为 release 附件上传）

### 2. 建 `latest.json` 放仓库

在仓库根目录（或 main 分支）放一个 `latest.json`，内容：

```json
{
  "version": 130,
  "minimum_version": 120,
  "url": "https://github.com/你的用户名/你的仓库/releases/latest",
  "notes": "本次更新：修复若干问题，新增 XX 功能"
}
```

字段说明：

| 字段 | 含义 |
| --- | --- |
| `version` | 最新版本号（= git 提交序号，与发布产物 v{N}-{hash} 的 N 一致） |
| `minimum_version` | 最低可用版本。本地低于它 → **强制更新**（全屏拦截，不可跳过） |
| `url` | 下载页地址（点「前往下载更新」打开它） |
| `notes` | 更新说明（可空） |

### 3. 每次发版更新 latest.json

打包后（会得到 `v{N}-{hash}`），把 `latest.json` 的 `version` 改成新的 N，推送到 GitHub。

- **普通更新**：本地版本 < `version` 且 >= `minimum_version` → 弹「有新版」，可稍后
- **强制更新**：本地版本 < `minimum_version` → 启动即全屏拦截

## 版本号约定

- 版本号 = `git rev-list --count HEAD`（当前 129）
- build.rs 编译时自动注入，无需手动同步
- `latest.json` 的 version 必须用同样的 git 提交序号

## 当前局限（后续可加）

1. **引导下载**：目前是「检测 + 提示 + 打开 GitHub 下载页」，用户手动下载替换。尚未实现自动下载 + 自替换 exe（需 updater 代理进程 + 代码签名，风险较高）
2. **无签名校验**：latest.json 本身走 HTTPS，但下载的 exe 未做 SHA256 校验（当前只跳转下载页，未自动下载，故暂不需要）
