# 联网更新接入说明（GitHub Releases）

## 现状

完整自动更新链路已实现（v130）：**检测 → 弹窗 → 下载（SHA256 校验）→ 自替换**。
后端通过 `ureq`（schannel）拉取 `latest.json`，用 git 提交序号作版本号比较。

## 需要你做的三件事

### 1. 填真实仓库地址

编辑 `app/src-tauri/src/update.rs`，把占位的 `UPDATE_MANIFEST_URL` 改成你的仓库：

```rust
const UPDATE_MANIFEST_URL: &str =
    "https://raw.githubusercontent.com/你的用户名/你的仓库/main/latest.json";
```

### 2. 建 `latest.json` 放仓库

```json
{
  "version": 131,
  "minimum_version": 120,
  "url": "https://github.com/你的用户名/你的仓库/releases/latest",
  "download_url": "https://github.com/你的用户名/你的仓库/releases/download/v131/CDiskSavior-Portable.exe",
  "sha256": "完整包的 sha256 十六进制（可留空则跳过校验）",
  "notes": "更新说明，支持多行"
}
```

字段说明：

| 字段 | 含义 |
| --- | --- |
| `version` | 最新版本号（= git 提交序号，与发布产物 v{N}-{hash} 的 N 一致） |
| `minimum_version` | 最低可用版本。本地低于它 → **强制更新**（全屏拦截，不可跳过） |
| `url` | 网页地址（无 download_url 或校验失败时引导手动下载的兜底） |
| `download_url` | 完整包直链（.exe/.zip/.msi，用于自动下载；可空） |
| `sha256` | 完整包 SHA256（可空则跳过校验） |
| `notes` | 更新说明 |

### 3. 每次发版更新 latest.json + 上传 exe

1. 打包后得到 `v{N}-{hash}`，把 exe 上传到 GitHub Release 附件
2. 计算 exe 的 sha256：`certutil -hashfile CDiskSavior-Portable.exe SHA256`
3. 更新 latest.json 的 `version` / `download_url` / `sha256`，推送到 GitHub

## 更新流程（已实现）

| 环节 | 行为 |
| --- | --- |
| 触发 | 启动 5 秒后 + 每 1 小时 + 手动「检查更新」 |
| 版本比较 | git 提交序号数字比较 |
| 弹窗 | 新版本号 + changelog +「立即更新 / 稍后 / 跳过此版本」 |
| 去重 | 同一版本只提示一次；跳过版本持久化到 localStorage |
| 下载 | 后台流式下载 + 进度条 + SHA256 校验 + URL 白名单（仅 http(s) 且可执行扩展名） |
| 自替换 | 写替换脚本 → 等旧进程退出 → 备份 → 覆盖 → 校验失败回滚 → 重启 |

## 当前局限

1. **增量更新不适用**：CDiskSavior 是编译型 exe，无源码包可增量替换，只有完整包路径
2. **无代码签名验签**：只做 SHA256 完整性校验（防损坏/篡改），未做 Authenticode 签名验证
