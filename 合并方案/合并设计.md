### 3.1 旧名迁移（改名带来的两项必做）

1. **旧服务清理（安全相关）**：安装器 `NSIS_HOOK_PREINSTALL` 必须先 `sc.exe stop` + `disk-butler-svc.exe uninstall` 清除旧 `DiskButlerScanSvc`（LocalSystem），否则留下无人管理的孤儿服务。
2. **旧数据导入**：R3 legacy 探测链在 WindowsClear 之前增加一级——disk-butler 旧标识符 `com.diskbutler.app` 的 appDataDir（`scan-cache-*.json` / `cleanup-stats.json`），存在则提示导入。

### 3.2 默认迁移根的运行时解析（不写死盘符）

`target_root` 的默认值在**首次进入 M4 时解析**，算法：

```
1. 枚举所有本地固定磁盘          GetDriveTypeW == DRIVE_FIXED
2. 排除系统盘                    %SystemDrive%
3. 排除 OneDrive 同步根          路径前缀比对 %OneDrive% / %OneDriveConsumer%
4. 在剩余候选中取「剩余空间最大」者   GetDiskFreeSpaceExW；并列时取盘符序最小
5. target_root = <该盘>:\CDisk Savior
```

**边界情形**：

| 情形 | 行为 |
| --- | --- |
| 无任何候选（单盘机器） | M4 首页显示"未找到可迁移的目标磁盘"，引导用户接入磁盘后重试；不给出会失败的默认值 |
| 候选盘剩余空间普遍过小（如全部 < 10 GB） | 仍按规则给出默认，但 UI 醒目提示空间紧张（真正拦截在 R9 迁移前预检） |
| 用户已保存过 `target_root` | **以用户值为准**，不再自动变更（包括换盘/拔盘后也不悄悄改，只在迁移预检时报错） |
| legacy 导入 | `target_root` 不继承旧值（用户定案），走本节规则给新默认；`scan_sources` 与历史照常导入 |

## 6. 关键设计决策（C1–C8，均为修订后定稿版）

### C1 迁移（M4）与孤儿目录清理（M3）的互斥防护

**机制**：M4 把 `%LOCALAPPDATA%\Foo` 移到 `G:\CDisk Savior\Local\Foo` 并在原位留下 Junction。
M3 的 `scan_orphan_dirs` 枚举 AppData 顶层目录，按知识库判定"无主 → 可清理"。

**已核验的现状**：disk-butler 的 `clean_orphans` 有两道闸门——当场重扫白名单 + `is_safe_residue_path` 的
`canonicalize()`（会把 junction 解析为真实目标，跨盘目标必在安装根之外 → 拒绝）。因此**跨盘 junction 实际不会被删**。
但该防线是**隐式的**（依赖 canonicalize 副作用），且扫描侧无 reparse 过滤，导致 junction 仍会出现在清理清单里、
`dir_size` 穿过链接把目标盘大小显示为"可释放"——**UI 误导**。

**定稿消解（全部为显式实现）**：
1. M3 的 `scan_orphan_dirs` 前置过滤：候选目录命中 `FILE_ATTRIBUTE_REPARSE_POINT` 一律跳过并标记 `migrated`；
2. **双向共享** `protected_paths` 集合（M4 迁移历史的全部 `source_path` ∪ 磁盘现存 reparse 目录）；
   M3 清理前二次校验，命中即拒绝并提示"该目录已迁移至 `<目标>`"；
3. M4 迁移/回滚与 M3 清理共用**全局写锁**，串行执行；
4. M3 结果页把"已迁移目录"**单独成组、只读展示**，附"打开目标位置"按钮。

### C3 安装模式与提权架构

- **安装模式**：`perMachine` / NSIS（因需安装 LocalSystem 扫描服务）。
- **事实基线**（源码核验后）：目录联接 `mklink /J` **不需要管理员权限**（本地路径链接）；真正需要管理员的是
  Restart Manager 终止其他用户/系统进程、写 HKLM 启动项、DISM。
- **提权模型**：**按操作提权，蓝本为 disk-butler 的 `bloatware.rs:667 run_elevated_ps` 家族**——
  脚本 UTF-16LE + Base64 内联 `-EncodedCommand`、不向 `%TEMP%` 落地 `.ps1`、marker 文件确认真实执行。
  light-c **没有任何按操作提权实现**（依赖整机管理员），其 M5 全部功能需改造为本模型。
- **UAC 取消判定**：必须用专用退出码 **1223 (ERROR_CANCELLED)**，禁止用 `exit code == 1`（会被 inner 脚本正常返回误判）。
- **提权目标校验**（V26）：对将被提权执行的二进制校验所在目录为仅管理员可写（Program Files），或做哈希/签名校验。
- `installerHooks`：合并 disk-butler 的 `hooks.nsi` 与 light-c 的 `nsis/installer-hooks.nsh`，并加入 §3.1 的旧服务清理。

**短期并存**（不同入口互不干扰）；**中期收敛**到 light-c 自研引擎（覆盖 4 业务场景、不依赖外部 crate），
但牵动服务协议，放到 P8 之后（Q3）。

### C7 图标库与状态层

- `lucide-react` 统一取 **1.27**，light-c 的图标名按 `tsc` 报错逐个修（Q5）。
- 状态层**以 light-c 的 `zustand` + `react-query` 为准**（模块数量决定需要集中状态），disk-butler 页面改写为读写同一 store。

### C8 legacy 兼容（硬约束）

**legacy 探测链（首次启动一次性执行，按优先级）**：

| 级 | 探测源 | 路径 | 用途 |
| --- | --- | --- | --- |
| ① | 新位置 | `<appDataDir>/relocate/config.json` | 主位置 |
| ② | disk-butler 旧标识符 | `com.diskbutler.app` 的 appDataDir | `scan-cache` / `cleanup-stats` 导入 |
| ③ | WindowsClear 配置 | 原 exe 同级目录 `config.json` | 导入 `scan_sources`；**`target_root` 不继承旧值，采用新默认 `G:\CDisk Savior`** |
| ④ | WindowsClear 历史 | `%LOCALAPPDATA%\tanaer\WindowsClear\data\history.json` | **重建 `protected_paths` 的关键数据源** |
| ⑤ | 兜底 | 提示用户手动指定旧安装目录 | 覆盖便携/换机场景 |

**三条铁律**：
1. **`config.json` 与 `history.json` 可能不一致**（target_root 改过盘符而旧迁移未动）——
   回滚与 `protected_paths` **必须逐条取 history 记录里的真实 `target_path`**，不能只信 config；
2. M4 的 `get/save_relocate_config` **原样读写 legacy `config.json` 的格式**（`scan_sources` 结构不变）；
3. `target_root` 默认值**运行时解析**（§3.2：系统盘以外的本地固定磁盘中剩余空间最大者，目录名固定 `CDisk Savior`），
   不继承 legacy 旧值、不写死盘符。目录名含空格无碍——M4 经 FSCTL 建 Junction 后无 cmd 转义问题。
