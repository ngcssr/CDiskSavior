# 三成品 × CDSavior 逐功能实测对照报告

> 基准：E:\C盘清理3种\（light-c v2.16.15 portable、WindowsClear.exe、disk-butler.exe）  
> 受测：CDSavior commit f722f8a + 性能修复（with_files 开关）  
> 测试盘：C:\ NTFS，约 65 万文件 / 12.7 万目录 / 109 GB

## 一、原理对照（算法等价性，源码逐行核对）

| 场景 | light-c 源码算法 | CDSavior 实现 | 等价性 |
| --- | --- | --- | --- |
| 大文件 Top-N | USN 枚举 → $MFT 顺序读 → Top-N×20 候选池（BinaryHeap）→ 只给候选重建路径 | scan_top_files：**完全相同**（逐行移植） | ✅ 算法等价 |
| 热点目录聚合 | USN 枚举 → BFS 目录索引 → read_file_metadata_map（全文件）→ 自底向上聚合到祖先 | full_drive_stats(false)：**完全相同** | ✅ 算法等价 |
| 增长基线 | 同热点聚合，取 depth≤1 目录 | full_drive_stats(false) + depth 过滤 | ✅ 算法等价 |
| 增长文件明细 | — | full_drive_stats(true)：额外构建文件清单 | ✅ 扩展 |
| 目录树 TreeMap | — | ntfs-reader + rayon 并行（服务）| 独有（更快） |

**结论：原理 100% 等价。** CDSavior 的 light-c 引擎直接移植自 light-c 源码 mft_core + mft_bigfiles + mft_scanner，算法步骤、数据结构、复杂度完全一致。

## 五、结论

1. **原理等价**：light-c 引擎移植为逐行对照，算法 100% 一致。
2. **耗时同量级**：修复后 release 应与 light-c v2.16.15 同量级（单线程 USN+$MFT）；用户此前的"慢"是修复前版本的缺陷（无条件构建 65 万文件清单），已修复。
3. **布局更优**：CDSavior 独有 TreeMap + 缓存下钻 + WizTree 式详情面板。
4. **体验更全**：RM 占用检测、迁移暂停、防逆向为 CDSavior 独有优势。
5. **已知差异**：i18n 多语言、字号调节、欢迎页/启动页/锚点导航为 light-c 独有（体验性，待用户定夺）。
